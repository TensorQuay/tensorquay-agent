# ADR-0017: Dependency licence policy

## Status

Accepted; amended 2026-09-27 (point 0, the Product Owner's rule; the scope; point 8, third-party images); point 9
(an advisory ignore for zip) accepted 2026-10-17 by the Product Owner, its zip ignore removed 2026-10-21 (calamine
0.37.0 takes zip 9); point 10 (unmaintained notices are resolved, not ignored) 2026-10-18 by the Product Owner

## Date

2026-09-22

## Context

The product is Apache-2.0 and must stay redistributable without copyleft obligations on its own code. A strict
"permissive only" allow list rejects packages that every modern web stack depends on: MPL-2.0 libraries
(lightningcss under Tailwind and Vite, axe-core under the accessibility lint), CC-BY-4.0 data (caniuse-lite) and
the LGPL-3.0 prebuilt libvips binaries that Next.js installs as an optional dependency of its image optimiser.

## Decision

0. **The rule (Product Owner, 27 Sep 2026): everything the product ships uses Apache-2.0-compatible licences.**
   The points below apply it to each kind of thing we ship.

Scope: this policy governs code the product links, bundles or vendors (Rust crates, npm packages, copied
sources) and, since 27 Sep 2026, every third-party image our compose files name (point 8). It does not govern
infrastructure an operator chooses and runs themselves (their host operating system, Docker Engine, Firecracker, a
database or service of their own), which is chosen by its own licence.

1. Allowed everywhere, Rust and web: Apache-2.0 (with or without the LLVM exception), MIT, MIT-0, BSD-2-Clause,
   BSD-3-Clause, ISC, 0BSD, Unlicense, CC0-1.0, BlueOak-1.0.0, Python-2.0, Zlib, BSL-1.0, Unicode-3.0 and
   Unicode-DFS-2016; and the OpenSSL licence (BSD-style, attribution) for TLS crypto crates only, as a named
   `cargo deny` exception with its notice in the notices file.
2. Allowed as an unmodified dependency only: MPL-2.0. The project never modifies or vendors MPL-2.0 files, so its
   file-level copyleft never attaches to project code. MPL-2.0 is explicitly compatible with Apache-2.0.
3. Allowed for data packages: CC-BY-4.0, with attribution recorded in the third-party notices, and
   CDLA-Permissive-2.0 (the Mozilla CA root bundle shipped by `webpki-roots`), which imposes no obligation on the
   product.
4. LGPL is not allowed, in any form (Product Owner decision, 22 Sep 2026). When a framework pulls an LGPL optional
   dependency, the dependency is removed from the install and the feature that needs it is disabled. Today: Next.js's
   optional `sharp` (libvips binaries under `@img/`) is excluded from the install and image optimisation is turned
   off. The policy file has no exception mechanism; a forbidden licence fails the gate regardless of the package.
5. Never: GPL, LGPL, AGPL, SSPL, BUSL, EUPL, any non-commercial or "see licence in file" declaration, and packages
   with no licence field. A blocked package is replaced or the feature is dropped; the allow list is not extended ad hoc.
6. The policy is data: `deny.toml` for Rust and `web/licenses.json` for the web (an `allow` list and a `forbidden`
   list), each read by its gate. Packages whose licences require notices (MPL-2.0, CC-BY-4.0) are listed in
   `THIRD-PARTY-NOTICES.md`, regenerated by the web checker's notices mode at each release.
7. Container images the project builds, such as the runtime image, are aggregates (clarified 23 Sep 2026). The base
   distribution's packages, including GPL programs such as `bash` and `git`, run as separate programs and are never
   linked with project code. Like the host operating system, they are outside the allow list. Distributing such an
   image carries those packages' own obligations: each release publishes the image's package list with exact versions
   and the location of the matching source packages.
8. **Third-party images in our compose files** (amended 27 Sep 2026). An image a compose file under `deploy/` names,
   other than our own `tqa-*` images, is on the approved list `deploy/third-party-images.toml` with its repository,
   the digest it is pinned by, its licence (an Apache-2.0-compatible SPDX id, or PostgreSQL's licence) and the source
   of that licence. Gate G-05-images (`tools/check-images.py`, SEC-030) fails on:
   - an image off the list;
   - an unpinned image, or one pinned by another digest;
   - a listed licence outside the allowed set;
   - an entry no compose file uses.
   **Never allowed**, whatever the image: source-available or enterprise licences (a core under an open licence with
   enterprise parts under a subscription licence counts as such), BUSL, SSPL, the Elastic licence, the Commons Clause,
   AGPL, GPL and LGPL for the image's own software. Point 7 still applies to the distribution packages inside an image.
   Adding an image to the list is a reviewed change.
9. **An advisory ignore in `deny.toml`** (accepted 17 Oct 2026). G-05 (`cargo deny`) fails on any RustSec advisory.
   An ID goes in `[advisories] ignore` only by an amendment here, naming the IDs, the evidence that our code can't
   reach the flaw, the gate that keeps that true, and when the ignore goes. **Today there is none.** The one there was,
   and why it went:
   - **What it was:** RUSTSEC-2026-0367, RUSTSEC-2026-0368 and RUSTSEC-2026-0369, in zip 8.6.0 and fixed in zip
     9.0.0, all in zip's extraction API (`ZipArchive::extract` and its variants, `ZipStreamReader::extract`). Ignored
     on 17 Oct 2026 because calamine 0.36.1, then the newest release, required `zip ^8.6`, and neither our code nor
     calamine calls that API: both open an archive and read its entries (the Product Owner's decision, 17 Oct 2026).
   - **Why it went (21 Oct 2026):** calamine 0.37.0 (18 Oct) requires `zip ^9.0`. The gateway pins calamine 0.37.0
     and zip 9.0.5, the three IDs left `deny.toml`, and the TEST-PLAN §19a entry went with them, as this point said
     they would. Our zip calls (`ZipArchive::new`, `len`, `by_index`, `by_name`, `ZipFile::size`,
     `ZipError::UnsupportedArchive` with `PASSWORD_REQUIRED`, and the tests' `ZipWriter`) are the same in zip 9.
   - **calamine 0.38.0 (7 Nov 2026):** RUSTSEC-2026-0436 (a panic and an unbounded allocation in calamine's compound-file
     parser on a crafted `.xls` or `.xlsb`) failed G-05's advisories on calamine 0.37.0; the gateway pins 0.38.0, the
     fixed release. zip stays 9.0.5, and the preview's tests (unit and database) pass unchanged.
   - **The gate stays:** G-05-zip (`tools/check-zip-reads.py`, SEC-063) still fails if any Rust source under `crates/`
     names the extraction API. We only read entries, and zip 9.0.1 to 9.0.3 fixed that API again. Its stale check
     covers only these three IDs: if `deny.toml` ignores any of them again, it fails once the lock holds no zip 8 or
     calamine moves on from 0.36.1. Any other ignore needs its own gate, as this point asks.
10. **An unmaintained notice is resolved, not ignored** (the Product Owner, 18 Oct 2026). `unmaintained = "all"` stays,
    and point 9's ignore is for a flaw our code can't reach, never for a crate nobody maintains: such a crate is removed
    or replaced. The first case: RUSTSEC-2026-0370, RUSTSEC-2026-0371 and RUSTSEC-2026-0372 (`zvariant`, `zbus_names`
    and `zvariant_derive`, merged into zbus 6.0.0) came in through the `atspi` crate (0.30) on zbus 5, which has no
    release on zbus 6. The computer tool's accessibility reader is now our own on zbus 6 (ADR-0039 slice 2, amended the
    same day), and the lock holds no zbus 5 crate.

## Consequences

The web stack installs cleanly under the gate once `sharp` is excluded. Any future MPL-2.0 dependency must never be
patched in place. There are no per-package exceptions; a blocked package is removed or replaced. Release notes carry
the notices file. An advisory ignore (point 9) is an exception to G-05, never to the licence rules, and lasts only
as long as its stated reason.
